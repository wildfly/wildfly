# Build and test subsystem changes

The root [README.md](../README.md) requires JDK 17 or newer, Maven 3.9 or newer, and at least 4096 open files on Unix-like systems. Check `java -version`, `./mvnw -v`, and `ulimit -n` first. This checkout's wrapper selects Maven 3.9.16 from `.mvn/wrapper/maven-wrapper.properties`; it may download Maven on first use. `pom.xml` compiles for Java 17. Use `./mvnw` on Unix-like systems or `mvnw` on Windows.

The [README](../README.md) explains `build/` (Maven artifact resolution, useful for local module iteration) and `dist/` (a full distribution). After an initial build, install a changed subsystem artifact before restarting a `build/` server; use the appropriate distribution or feature-pack build when testing packaging.

For a fast local check, start with `./mvnw -pl <module> -am test` to compile and run the affected module's unit/subsystem tests with reactor dependencies. Use `./mvnw -pl <module> -am install` if tests need locally installed artifacts. In a module with suitable tests, `-Dtest=<TestClass>` narrows Surefire; check its `pom.xml` and reports to ensure the intended tests actually ran. Do not infer that a successful module test ran server integration or mixed-domain tests.

Find relevant tests with `rg -n '<subsystem-name>|<attribute-name>' <module>/src/test testsuite` and inspect the testsuite module's `pom.xml` for profiles and test prerequisites. The [testsuite README](../testsuite/README.md) links the maintained [integration testsuite guide](../docs/src/main/asciidoc/_testsuite/WildFly_Integration_Testsuite_User_Guide.adoc). That guide says to use `install` for testsuite runs because earlier phases can miss setup. Build/install WildFly first (`./mvnw install`, or an appropriate build with skipped tests), then use `./mvnw -f testsuite/pom.xml install -Dts.<group>` for the group that owns the test. A single testsuite module can use `-pl testsuite/integration/<module>` only after ancestor modules have created the server copies. For a single class use `-Dtest=<TestClass>` with the appropriate group and read the guide's warning about Surefire executions and default server configuration.

Subsystem XML/model and transformer tests usually live in the subsystem module; server behavior tests may live in `testsuite/integration/`, `testsuite/domain/`, or `testsuite/mixed-domain/`. Verify the actual test count and failures in Surefire reports. If a needed legacy artifact, server build, toolchain, or external service is unavailable, report that limitation and the exact command attempted.
