[[Elytron_Java_Security_Manager]]
= Elytron WildFly Java Security Manager

== Runtime support

WildFly variants based on Jakarta EE 11, including standard WildFly 40 and later, do not support running with the Java Security Manager enabled.
All Jakarta EE 11 specifications have removed dependencies on the Java SE Security Manager, consequently, starting a xref:Different_Flavors_of_WildFly{outfilesuffix}[standard WildFly or WildFly Preview] with the Security Manager activated will result in a boot failure.

This is not strictly a limitation of the underlying JDK.
The community decided to deprecate the Java Security Manager with Java SE 17. The full details are described in https://openjdk.org/jeps/411[JEP 411: Deprecate the Security Manager for Removal].
And although you can still run a Jakarta EE 11 application on Java SE 17, that does not make it functional.

WildFly 42 startup scripts reject attempts to enable the Security Manager using `-secmgr`, `SECMGR=true`, or the `-Djava.security.manager` system property, including `-Djava.security.manager=allow`.
This applies even when the JDK supports the Security Manager.

The WildFly EE 10 variants of WildFly 40 and 41, and earlier WildFly releases that support the Security Manager, retain their version-specific support, subject to the JDK versions they support.
For instructions for those releases, see the
https://docs.wildfly.org/41/WildFly_Elytron_Security.html#Elytron_Java_Security_Manager[WildFly 41 Security Manager documentation].

== The legacy Security manager subsystem

Beginning with WildFly 42, the `org.wildfly.extension.security.manager` extension and its `security-manager` subsystem are retained only as a legacy management model; starting a WildFly 42 standalone server with the extension in the configuration will result in a boot failure, unless the server is started in admin-only mode.

It's completely valid for a standard WildFly 42 domain mode Domain Controller to have the `security-manager` subsystem in its `domain.xml` file, if the profiles that include the subsystem are used in server groups where all the servers are running WildFly 39 or earlier or the WildFly EE 10 variant of WildFly 40 or 41.
