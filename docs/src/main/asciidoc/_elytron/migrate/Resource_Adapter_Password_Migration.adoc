[[Resource_Adapter_Password_Migration]]
= Resource Adapters

ifdef::env-github[]
:tip-caption: :bulb:
:note-caption: :information_source:
:important-caption: :heavy_exclamation_mark:
:caution-caption: :fire:
:warning-caption: :warning:

Resource adapter connection definitions referenced the same PicketBox login modules as
datasources, through the `security-domain`, `security-domain-and-application` and
`recovery-security-domain` attributes of the `connection-definition` resource, so the
warning in <<Datasource_Password_Migration,Datasource Passwords>> applies to them
unchanged. A connection definition that still uses one of those attributes is rejected
with `WFLYJCA0123: Connection definition <name> from resource adapter <name> is
configured to require the legacy security subsystem, which is not present`.

Unlike a datasource, a connection definition has no `user-name` or `password` attribute of
its own, so the identity is always supplied by Elytron. Replace the legacy security domain
with an `authentication-context`, which in turn takes the password from a credential
store. As for a datasource, `elytron-enabled` has to be set to `true` on the same
connection definition:

[source,options="nowrap"]
----
batch
./subsystem=elytron/authentication-configuration=ra-auth:add( \
    authentication-name=sa, \
    credential-reference={store=mycredstore, alias=my-cd})
./subsystem=elytron/authentication-context=ra-context:add( \
    match-rules=[{authentication-configuration=ra-auth}])

./subsystem=resource-adapters/resource-adapter=my-ra/connection-definitions=my-cd:undefine-attribute(name=security-domain)
./subsystem=resource-adapters/resource-adapter=my-ra/connection-definitions=my-cd:write-attribute(name=elytron-enabled, value=true)
./subsystem=resource-adapters/resource-adapter=my-ra/connection-definitions=my-cd:write-attribute(name=authentication-context, value=ra-context)
run-batch

reload
----

The `security-domain-and-application` attribute, which combined a security domain with the
application supplied identity, is replaced by `authentication-context-and-application` in
the same way.

A recovery identity that used `recovery-security-domain` is migrated either to
`recovery-username` together with `recovery-credential-reference`, or to
`recovery-elytron-enabled` together with `recovery-authentication-context`.
