[[Singleton_MSC_services]]
= Singleton MSC services

ifdef::env-github[]
:tip-caption: :bulb:
:note-caption: :information_source:
:important-caption: :heavy_exclamation_mark:
:caution-caption: :fire:

The singleton service facility exposes a mechanism for installing an MSC service such that the service only starts on a single member of a cluster at a time.
If the member providing the singleton service is shutdown or crashes, the facility automatically elects a new primary provider and starts the service on that node.
In general, a singleton election happens in response to any change of membership, where the membership is defined as the set of cluster nodes on which the given service was installed.

[[installing-an-msc-service-using-an-existing-singleton-policy]]
== Installing an MSC service using an existing singleton policy

While singleton MSC services have been around since AS7, WildFly adds the ability to leverage the singleton subsystem to create singleton MSC services from existing singleton policies.

To install a singleton service from a deployment, expose a service activator that implements `org.wildfly.clustering.singleton.service.SingletonServiceActivator`:

[source,java,options="nowrap"]
----
@MetaInfServices(org.jboss.msc.service.ServiceActivator.class)
public class MyServiceActivator implements org.wildfly.clustering.singleton.service.SingletonServiceActivator {
    @Override
    public void activate(org.wildfly.clustering.singleton.service.SingletonServiceActivatorContext context) {
        // Any service installed into this target will be instrumented as a singleton service
        ServiceTarget target = context.getServiceTarget();
        ServiceBuilder<?> builder = target.addService();
        builder.provides(ServiceName.parse("my.service.name"));
        Service service = new MyService();
        builder.setInstance(service).install();
    }
}
----

To install singleton services using a non-default singleton policy, override the `getSingletonPolicy()` method accordingly.

e.g.
[source,java,options="nowrap"]
----
@MetaInfServices(org.jboss.msc.service.ServiceActivator.class)
public class MyServiceActivator implements org.wildfly.clustering.singleton.service.SingletonServiceActivator {
    @Override
    public void activate(org.wildfly.clustering.singleton.service.SingletonServiceActivatorContext context) {
        // ....
    }

    @Override
    public String getSingletonPolicy() {
        return "foo";
    }
}
----


[[singleton-msc-service-metrics]]
== Singleton MSC Service metrics ==

The singleton subsystem registers a set of runtime metrics for each singleton MSC service installed via a given singleton policy.

is-primary:: Indicates whether the node on which the operation was performed is the primary provider of the given singleton service
primary-provider:: Identifies the node currently operating as the primary provider for the given singleton service
providers:: Identifies the set of nodes on which the given singleton service is installed.

e.g.

----
/subsystem=singleton/singleton-policy=foo/service=my.service.name:read-attribute(name=primary-provider)
----


[[installing-an-msc-service-using-dynamic-singleton-policy]]
== Installing an MSC service using dynamic singleton policy

Alternatively, you can override a singleton policy dynamically, which is particularly useful if you want to use a custom singleton election policy.
`org.wildfly.clustering.singleton.service.SingletonServiceTarget` is a specialisation of the `org.jboss.msc.service.ServiceTarget` interface, that creates `org.wildfly.clustering.singleton.service.SingletonServiceBuilder` instances, which itself is a specialisation of the `org.jboss.msc.service.ServiceBuilder` interface,
and includes support for specifying an election policy, an election listener, and, optionally, a quorum required before electing the primary provider of the singleton.

The SingletonElectionPolicy is responsible for electing a member to operate as the primary singleton service provider following any change in the set of singleton service providers.
Following the election of a new primary singleton service provider, any registered SingletonElectionListener is triggered on every member of the cluster.

e.g.

[source,java,options="nowrap"]
----
public class MySingletonElectionPolicy implements org.wildfly.clustering.singleton.election.SingletonElectionPolicy {
    @Override
    public GroupMember elect(List<GroupMember> candidates) {
        // ...
        return ...;
    }
}

public class MySingletonElectionListener implements org.wildfly.clustering.singleton.election.SingletonElectionListener {
    @Override
    public void elected(List<GroupMember> candidates, GroupMember elected) {
        // ...
    }
}

@MetaInfServices(org.jboss.msc.service.ServiceActivator.class)
public class MyServiceActivator implements org.wildfly.clustering.singleton.service.SingletonServiceActivator {
    @Override
    public void activate(org.wildfly.clustering.singleton.service.SingletonServiceActivatorContext context) {
        org.wildfly.clustering.singleton.election.SingletonElectionPolicy policy = new MySingletonElectionPolicy();
        org.wildfly.clustering.singleton.election.SingletonElectionListener listener = new MySingletonElectionListener();
        int quorum = 3;
        // Any service installed into this target will be instrumented as a singleton service
        org.wildfly.clustering.singleton.service.SingletonServiceTarget target = context.getServiceTarget();
        org.wildfly.clustering.singleton.service.SingletonServiceBuilder<?> builder = target.addService()
                .withElectionListener(listener)
                .withElectionPolicy(policy)
                .requireQuorum(quorum);
        builder.provides(ServiceName.parse("my.service.name"));
        Service service = new MyService();
        org.wildfly.clustering.singleton.service.SingletonServiceController<?> controller = builder.setInstance(service).install();
    }
}
----
